# P0 and P1 Evidence Gates

Read this file when screening or validating a candidate topic.

## P0: Should this candidate be investigated further?

### Recommended dimensions

| Dimension | Weight | Core question |
|---|---:|---|
| Research importance | 20 | Does the problem matter theoretically, practically, or institutionally? |
| Disciplinary fit | 15 | Does it belong to the user's degree and field? |
| Case distinctiveness | 15 | Does the case reveal a mechanism or boundary not visible in ordinary cases? |
| Evidence entry points | 20 | Are there identifiable official, company, regulatory, or database sources? |
| Research differentiation | 15 | Is the difference more than replacing one company with another? |
| Feasibility and scope | 15 | Can the question be answered within a master's timeline and data access? |

### Decision

- **Pass**: strong problem, clear disciplinary fit, and plausible evidence path.
- **Conditional pass**: promising topic with one or two specific evidence risks to resolve in P1.
- **Fail**: no important problem, no accessible evidence path, or a mismatch with degree requirements.

### P0 red flags

- the title is built from policy slogans without an observable problem;
- novelty depends only on a recent company or industry;
- the topic requires internal records that are unlikely to be available;
- the case contains many events but no coherent analytical chain;
- the intended conclusion is already embedded in the title;
- the topic conflicts with advisor instructions or group restrictions.

## P1: Can the available evidence support the proposed paper?

### Required evidence tests

1. **Primary-source test**: core facts have company, regulatory, legal, standard-setting, or official support.
2. **Continuity test**: the central process can be observed across meaningful dates or stages.
3. **Definition test**: major data fields have known scope, unit, boundary, and calculation basis.
4. **Pilot test**: at least one small analysis has been completed.
5. **Literature test**: foundational claims and intended differences are supported by verified literature.
6. **Claim-boundary test**: the proposal distinguishes what the evidence can show from what it cannot identify.

### Evidence matrix

| Research proposition | Required evidence | Available source | Source status | Gap | Alternative |
|---|---|---|---|---|---|
| Why the change occurred | policy, customer, governance, or strategy documents |  |  |  |  |
| How the mechanism operates | rules, systems, responsibilities, data, process evidence |  |  |  |  |
| What changed | longitudinal metrics, text, events, or practices |  |  |  |  |
| What the result means | triangulated case evidence and literature |  |  |  |  |

### Pilot-analysis options

Choose one that matches the proposed method:

- code a small sample of reports using a draft coding scheme;
- reconstruct one accounting or governance event;
- build a three-to-five-year data table;
- compare original and restated definitions;
- test whether an event date and return window are identifiable;
- trace one policy or customer requirement into a company control or disclosure.

### P1 decision

- **Pass**: the pilot works and the remaining gaps do not undermine the central question.
- **Conditional pass**: the topic remains viable after narrowing claims, time period, or outcome scope.
- **Fail**: the central mechanism or result depends on unavailable data, unverifiable sources, or unsupported causal inference.

## Scoring discipline

Scores support comparison; they do not replace evidence. Record the reason, source, and uncertainty behind every high score. Re-score when advisor feedback, duplicate-topic restrictions, or evidence availability changes.

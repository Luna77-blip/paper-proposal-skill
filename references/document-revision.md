# Proposal Document Revision

Read this file when editing an existing Word proposal or adapting it to advisor feedback.

## Versioning

Default to a new version unless overwrite permission is explicit.

Recommended filename pattern:

`proposal-[case-or-topic]-VNN-[purpose].docx`

Maintain a short change log containing:

- source version;
- date;
- sections changed;
- substantive decisions;
- unresolved items.

## Feedback classification

Classify each advisor comment before editing:

| Type | Typical meaning | Required response |
|---|---|---|
| Topic | Wrong domain or unimportant question | Revisit candidate selection or P0 |
| Scope | Too small, broad, or fragmented | Redesign the question chain |
| Evidence | Insufficient or inaccessible data | Re-run P1 or narrow claims |
| Method | Method cannot answer the question | Replace or remove the method |
| Discipline | Weak accounting, finance, audit, or governance fit | Reframe constructs and evidence |
| Writing | Unclear, defensive, repetitive | Local prose revision |
| Format | Template, table, figure, citation issue | Preserve content and repair layout |

Do not respond to a scope problem by only lengthening the title.

## Local-edit discipline

When preserving user formatting:

1. inspect the complete document first;
2. identify exact target paragraphs, tables, figures, and references;
3. edit the smallest necessary units;
4. avoid changing title, theory, methods, or formatting outside the requested scope;
5. preserve colors, fonts, numbering, captions, and table dimensions;
6. verify the changed text and the unchanged protected sections;
7. render and inspect all pages.

## Claim-language correction

Use causal language only when the design identifies causality.

| Unsupported wording | Safer wording |
|---|---|
| promotes performance | supports or is associated with performance |
| leads to international expansion | provides information or management support for international operations |
| proves effectiveness | provides case evidence of operation or observed change |
| creates universal model | summarizes a mechanism or transferable consideration |
| customer requires | publicly stated customer requirement or company-disclosed response |

## Remove defensive writing

Delete sentences whose only function is to anticipate criticism and that do not advance the argument. State the chosen scope directly. Keep limitations where they change interpretation, evidence use, or method validity.

## Figure and table requirements

- assign a number and descriptive title;
- include unit, period, definition, and source;
- preserve an editable source when requested;
- distinguish reported, recalculated, restated, and inferred values;
- explain breaks in series and boundary changes;
- ensure visual claims match the table data.

## Delivery report

Tell the user:

- what was changed;
- what was explicitly preserved;
- what was verified;
- the exact output location;
- any decision still requiring user or advisor confirmation.
